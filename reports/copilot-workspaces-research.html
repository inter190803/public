01 / Executive Summary
事実 推測

結論：「単なる名称変更」ではなく、個人用ノートから“チーム共同作業ハブ”への構造転換

事実 Microsoft は 2026年10月後半〜11月（Microsoft Ignite 2026 および Message Center MC1559638）にかけて、従来の Copilot ノートブック（Copilot Notebooks）を Copilot ワークスペース（Copilot Workspaces） へと改称・機能拡張しました。背景には、個人単位の調べもの・タスク管理を担う Copilot プロジェクト（Copilot Projects） との役割分離があり、ワークスペースは複数メンバーが同一コンテキスト・ライブカーソル・アクティビティフィード・グループ所有権を共有しながら AI と協働する「チームファースト」の作業空間として再定義されています。既存のノートブックは自動移行され、ファイルや共有設定はそのまま引き継がれます。

02 / Evolution & Changes 事実

変更点：「Copilot ノートブック」から「Copilot ワークスペース」へ何が変わったか

従来の Copilot ノートブック（MC1326520 / 2026年6〜8月展開）は、チャット・ファイル・ページ・会議メモを1か所に集約してグラウンディングする「永続コンテキストの器」として登場しました。しかし実務では「OneNote のノートブックと紛らわしい」「個人の調べものには良いが、複数人で同じプロジェクトを同時推進する機能（更新履歴やプレゼンス、所有権の共有）が弱い」という課題がありました。今回の Copilot ワークスペース（MC1559638） への改称は、これらを解消する機能拡張を伴う進化です。

03 / Architecture & Design Philosophy 事実

設計思想：なぜ Microsoft は「Workspaces」へ再編したのか（Work IQ と 3つの課題解決）

Microsoft Ignite 2026 で打ち出された「Copilot is the new operating system for work」というビジョンの核心には、人間と自律型エージェント（Autopilot 等）が同じ場・同じ記憶で協働するという設計思想があります。Copilot Workspaces は単なる UI 改善ではなく、従来の生成AIチャットが抱えていた3つの構造的課題を解決するために設計されています。

課題 1：毎回プロンプトをやり直す疲労

コンテキストの永続化と境界固定

通常のチャットはフロー型で流れ去り、毎回ファイルを再添付する必要があります。ワークスペースは「指定した資料群」を境界として固定し、その範囲内のみを根拠（グラウンディング）にすることで、ハルシネーションや無関係データの混入を防ぎつつ文脈を維持します。

課題 2：個人最適化（Single-player）の限界

マルチプレイヤー・チーム協働

1人の頭の中だけで AI と壁打ちしても、チーム合意や引き継ぎには使えません。Workspaces はチームメンバー全員が同じ参照知識・同じ編集キャンバス・同じ AI 対話結果を共有し、誰かが進めた結果を別メンバーが即座に引き継げる設計になっています。

課題 3：個人メモと共有業務の混在

Projects と Workspaces の明確分離

下書きや試行錯誤はホームタブ上の個人用 Copilot Projects で安全に完結させ、チーム展開の段階になったら Copilot Workspaces へ持ち込む（あるいは Project を丸ごと参照追加する）2段階のワークフローを前提としています。

Work IQ（組織知能レイヤー）における Workspaces の位置づけ

Ignite 2026 公式アーキテクチャ

Microsoft 365 内のファイル・メール・会議・チャットおよび Dynamics 365 / Power Platform を横断推論する知能基盤「Work IQ」は、以下4本の柱で構成されており、Workspaces はそのうちの「エージェント的推論・複雑課題解決の実行場」を担います。

1. Chat
対話インターフェースおよび Agent-to-Agent (A2A) 連携プロトコルの窓口。
2. Context
組織データをエージェントがすぐ使える入力へ自動構造化・グラウンディング。
3. Tools
権限を尊重しながら M365 エンティティや業務システムへ安全にアクションを実行。
4. Workspaces ★
人間とエージェント（Autopilot等）が継続的コンテキストを共有し共創する作業空間。

04 / Practical Workflows & Interactive Advisor
事実 推測

活用方法：実務での仕事の進め方と推奨ワークフロー

推奨される「個人 → チーム」2段階ワークフロー
STEP 1：個人で仕込む
Copilot Projects

雑多なメモ、初期調査チャット、個人タスクをホームタブで整理。まだ人に見せない生データを育てる。

STEP 2：チーム空間へ昇格
Copilot Workspaces

Project や確定資料・会議記録を参照として追加し、カスタム指示（出力形式・トーン）を設定してメンバーを招待。

STEP 3：成果物生成・共創
Pages / Office / 音声概要

ライブカーソルで同時編集しつつ Word/Excel/PPT 化、または Audio Overviews で音声化して関係者へ展開。

部門長・M365管理者における具体的活用パターン（6選）

1. 上位方針展開・部門予算/GAP管理 推測

本部長方針資料（PPTX/PDF）、部門予算Excel、前期GAP振り返りメールを参照に固定。カスタム指示に「課長向け伝達事項・数値根拠・期限を表形式で出力」と設定し、課長陣と同じワークスペースで部署別アクションを共同編集。

2. M365 技術導入プロジェクト（Intune / Defender 等） 推測

設計書（Word）、検証結果（Excel）、ベンダー定例の Teams 会議文字起こし、公式LearnのURLを1か所に集約。新任メンバーが参画してもワークスペースのアクティビティフィードと Copilot への質問だけで経緯を一発把握。

3. 会議起点の議事録・決定事項・課題管理 事実

Teams 会議（トランスクリプト・チャット・会議中共有ファイル）をそのまま参照として追加可能（有料ライセンス）。複数回の定例会議を横断して「前回からの未決課題リスト」を Copilot Pages へ生成し、全員でライブ更新。

4. カスタム指示（Custom Instructions）による品質標準化 事実

ワークスペースごとにプロンプトの前提条件（出力フォーマット、禁止事項、対象読者、トーン＆マナー）を固定可能。誰が質問してもチーム標準の形式で回答・成果物が出る環境を構築。

5. Audio Overviews（音声概要）による高速キャッチアップ 事実

ワークスペース内の参照資料（Word や OneNote ページ等最低1件以上）から、1名解説または2名対談ポッドキャスト形式の音声を生成（商業用 Entra ID アカウント向け）。長文資料を通勤中・移動中に耳で把握可能。

6. OneNote との双方向連携による現場メモ集約 事実

iPhone / iPad 版 OneNote からも Copilot ノートブック／ワークスペース機能が利用可能。外出先で OneNote にメモした内容を、デスクに戻って Web 版 `m365.cloud.microsoft` のワークスペースでチームと AI 加工する連携がスムーズ。

05 / Licensing Comparison 事実

ライセンスによる違い：M365 Copilot 保有者 vs 非保有者（Copilot Chat）

従来は有料の Microsoft 365 Copilot アドオンライセンス 保有者専用だったノートブック機能が、基本の Microsoft 365 Copilot Chat（対象となる Microsoft 365 Business / Enterprise 契約に標準付帯） ユーザーにも開放されました。これにより「有料ライセンス保有者と非保有者が混在する部門」でもワークスペースを基盤とした共同作業が可能になった一方、参照できるデータソースの種類・件数上限・AI機能には明確な境界線が引かれています。

06 / Specifications, Formats & Limits 事実

網羅仕様：対応形式・上限値・共有ルール・提供クライアント

1. 対応ファイル形式・参照ソース一覧

  • Microsoft Office / Copilot 形式：.docx, .pptx, .xlsx, .loop, .page, OneNote ページ／セクション／ノートブック
  • ドキュメント・テキスト：.pdf, .txt, .md, .rtf
  • 画像・動画メディア：.jpeg, .png, .mp4
  • M365 エコシステム参照（有料ライセンス中心）：Web URL、SharePoint サイト・ページ、OneDrive コンテンツ、Outlook メールスレッド（添付含む）、Teams チャット・会議（招待、議題、出席者、トランスクリプト、AI要約、共有ファイル）、Copilot Project

2. 定量上限・パフォーマンス目安（重要仕様）

  • アクティブなグラウンディング上限：1ワークスペースあたり先頭 100件の参照のみが回答生成の根拠に使用されます。101件目以降は無視されるため、不要な過去資料の整理または順序調整が必要です（※一部資料に「最大300件」の記載があるのは登録可能枠であり、Microsoft Learn の技術仕様上は先頭100件ルールが適用されます）。
  • Copilot Chat の上限：ライセンス非保有者は最大 50件 まで。
  • ドキュメント長の目安：M365 Copilot 標準準拠（要約・参照は 最大 約150万語 または 300ページ、Q&A・一般分析の最適長は 約7,500語未満、リライト最適長は 約3,000語未満）。
  • Audio Overviews：最低1件の参照ファイルが必須。日次利用上限の目安は 1日20回まで（構成・ライセンスにより変動）。
3. 共有・外部ゲストアクセスの厳格な制約 事実
  • 外部共有（ゲストアクセス）は非対応：Microsoft 公式ドキュメントに「Copilot ノートブック（ワークスペース）は外部共有をサポートしていません」と明記されています。社外パートナーを交えた共同作業には Teams 共有チャネルや通常の SharePoint / OneDrive 共有を使う必要があります。
  • リンク先ファイルの共有権限が必要：ワークスペースを共有すると内部のリンク先ファイルへのアクセスも自動付与されますが、共有する本人が各元ファイルに対する共有権限を持っている必要があります。
  • OneNote 連携の落とし穴：参照に OneNote のセクションやページを含めた場合、受信者がその中身を読むには OneNote ノートブック全体を別途共有する必要があります。
4. 提供クライアント・プラットフォーム対応 事実
  • Web / Copilot アプリ：m365.cloud.microsoft の左ナビゲーションおよび上部のアプリ起動ツール（ワッフルメニュー）からアクセス。
  • OneNote 統合：デスクトップ版・Web版および iOS（iPhone / iPad）版 OneNote から拡張ワークスペース機能へアクセスし、Web版と双方向同期。
  • モバイル（iOS / Android）：Teams 会議の参照追加や、自然言語でのページ編集指示（例：「このページを短くして」）、チャットからのページ自動作成に対応。
  • 対象プラン範囲：商用 Entra ID（Work / School）に加え、一般向け Microsoft 365 Personal / Family / Premium / Pro でも一部展開。

1. Microsoft 365 クラウドポリシー（Cloud Policy）による作成制御

Microsoft 365 Apps 管理センター（config.office.com）のクラウドポリシーでは、Loop 本体とは独立して Copilot ページ／ノートブック（ワークスペース）の有効・無効を制御できます。

ポリシー名 既定値 制御内容と運用のポイント
Create and view Copilot Pages and Copilot Notebooks
（Copilot ページと Copilot ノートブックを作成して表示する）		 有効 (Enabled) 無効化するとユーザーによる新規作成・表示を停止可能。Loop アプリ自体を無効化しても本ポリシーが有効なら、Copilot 専用の個人 SharePoint Embedded コンテナーのみ払い出される。完全停止するには Loop 側ポリシーと両方無効にする必要あり。
Enable code previews for AI-generated content in Microsoft Copilot Chat and Copilot Pages 有効 (Enabled) AI が生成した HTML / コード等のライブプレビュー描画を制御。セキュリティポリシー上サンドボックス外での描画を制限したい場合に無効化を検討。

2. PowerShell による SharePoint Embedded コンテナー監査

SharePoint 管理センター（SharePoint Embedded > Active/Deleted containers）および PowerShell では、所有アプリケーション ID a187e399-0c36-4b98-8f04-1edc167a0996（Loop）を指定して、ワークスペース・ページの保存コンテナーを一覧取得できます。 

# Copilot Pages / Workspaces / Loop マイワークスペースのユーザー所有コンテナーを全件取得
Get-SPOContainer -OwningApplicationId 'a187e399-0c36-4b98-8f04-1edc167a0996' | Where-Object { $_.OwnershipType -eq 'UserOwned' }

08 / Admin Checklist & Troubleshooting FAQ
事実 推測

展開前チェックリスト ＆ よくある質問・トラブルシューティング

展開前・移行期チェックリスト（M365管理者・部門長向け） クリックで開閉
Q1. これまでに作った「Copilot ノートブック」は消えたり作り直しになりますか？
事実 いいえ。既存の Copilot ノートブックは自動的に Copilot ワークスペースへ移行され、追加済みの参照ファイル、生成したページ、設定済みの共有権限はすべてそのまま保持されます。未共有だった個人用ノートが勝手に全員公開されることもありません。
Q2. 左メニューに「ワークスペース」が見当たらない場合はどうすればよいですか？
事実 Microsoft Copilot アプリ（m365.cloud.microsoft）の左ナビゲーションに表示されない場合は、画面左上のアプリ起動ツール（9点ワッフルメニュー）から「ワークスペース」を選択してください。なお、テナントへの段階的ロールアウト（2026年11月 Frontier → 12月 GA）途中では旧称「ノートブック」のまま表示される期間があります。
Q3. 参照ファイルを120件入れたのに、後半の資料について Copilot が答えてくれません。
事実 仕様上、登録自体は最大300件（Copilot Chat は50件）まで可能と案内されるケースがありますが、アクティブなグラウンディング（回答生成の検索対象）に使用されるのは先頭 100件の参照までです。101件目以降は無視されるため、不要になった資料を削除するか、参照リストの並び順で重要な資料を上位100件以内へ配置してください。
Q4. OneNote のページを参照に入れたワークスペースを共有したら、同僚が「閲覧できない」と言います。
事実 通常の Word/PDF 等と異なり、ワークスペース内に OneNote のセクションやページを参照として含めている場合、受信者がアクセスできるようにするには元の OneNote ノートブック全体を別途共有する必要があります。また、共有相手が Copilot ライセンス非保有者の場合、Teams / SharePoint / 内部 URL 等のプレミアムソースも参照できません。
Q5. 社外ベンダー（外部ゲストアカウント）をワークスペースに招待して共同作業できますか？
事実 できません。Microsoft 公式ドキュメントにおいて「Copilot ノートブック（ワークスペース）は外部共有をサポートしていません」と明記されています。社外協働が必要な成果物は、ワークスペース内で作成した後に Word / Excel / PowerPoint や通常の SharePoint ライブラリへ書き出して共有してください。

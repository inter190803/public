1. 製品の全体像と動作の仕組み（詳細）

Addness（公式サイト）は、アドネス株式会社（代表取締役：三上功太）が提供する「ゴールから、人とAIの仕事を一つにする」カンパニーブレインです。最大の設計思想は、バラバラのツールに散らばった目標・タスク・会話・議事録・ファイル・顧客・数字を「同じゴールの下」に集約し、接続したAIエージェントに都度ゼロから前提を説明しなくても続きから動ける状態を作る点にあります（機能一覧）。

1-1. ゴールツリーの構造と「理想・メモ・AIメモリ」

Addnessのゴールツリーは、組織の最上位目標から担当者の具体的な一歩までを単一の親子階層で管理します。単にタスクを並べるのではなく、各ゴールに「理想（達成状態の定義）」「メモ」「リソース（添付ファイルや議事録）」を持たせられる点が特徴です。ここに記載した内容がそのまま接続先AIへのコンテキストになります。

ツリーの構築は「①完了基準を言葉にする → ②最初の関門を1〜2個だけ見つける → ③自分やAIがこなせる粒度まで割る → ④責任者と期日を入れる」という4ステップで進めます。最初から完璧なツリーをすべて描き切ることは推奨されておらず、結果が返ってきたところで次の関門を足していく（差分駆動）運用が前提です。また、AIがそのゴールで作業すると、決めたこと・作ったもの・分かったことが「AIメモリ」としてゴールに自動蓄積されます（Addness公式 ゴール機能）。

1-2. 「今やるべきToDo」の生成と日次ループ

ゴールページには「ゴール由来のToDo」と「今やるべきToDo」が並びます。期日が今日になったゴールが勝手に「今やるべきToDo」へ入るのではなく、ゴール行頭の「＋」ボタンで人が選んで並べる仕組みです（ただしテンプレートのルーティンから自動生成されたゴールだけは、指定日に担当者の「今やるべきToDo」へ自動投入されます）。

ステータスは行頭のボタンで「未着手 → 実行中（✓）→ 完了（✓✓）」と遷移し、未完了のものは日付を跨いでも残り、完了したToDoは翌日（組織タイムゾーンの午前4時）に一覧から消えます。「今やるべきToDo」見出し横の「タスクをクリーニングする」を押すと、AIが溜まったToDoの整理案を出し、今日やるものを上から順に決める支援を行います。Focus以上のプランでは、Googleカレンダーの予定も同じリスト上に読み取り専用で表示されます（Slack・Googleカレンダー連携）。

1-3. 「アドる」の具体的な動作

「アドる」は、Addness上の文脈を外部AIエージェントへワンクリックで渡す起動トリガーです。ゴール行右側の「アドる」メニューには「進める」「壁打ちする」「質問する」の選択肢があり、「進める」を選ぶとそのゴールのURLと進め方を含んだ指示文が自動生成されます（ゴール機能）。

続けて「指示文をコピー」「Claudeで開く」「Codexで開く」を選択すると、Claude CodeやCodexなどのアプリが指示文の入力済み状態で起動し、送信するだけで作業が始まります。この仕組みはゴールだけでなく、アナリティクス画面の「このダッシュボードをアドる」「この定義をアドる」や、チャット・議事録・ドライブが紐づくゴールにも一貫して組み込まれています。

1-4. チャット・通知・コメントの位置づけ

Addnessのチャットは「ゴールのチャット」「グループ（チャンネル）」「DM」の3種類が左リストに1本で並びます。ここで最も重要な仕様は、「ゴールのチャットへの投稿＝そのゴールのコメント」という同一データモデルになっている点です（チャット・ハドル通話）。

スレッドでのやり取りは片付いたら「解決にする」でクローズでき、完了・期日変更などのアクティビティも同タイムラインに流れます（AIによる一括作業は「◯件のアクティビティ」に折りたたまれます）。そのため、雑談ではなく「仕事の話」をゴールのチャットに集めるだけで、経緯がそのままゴールの文脈として残り、後から「アドる」でAIが参照できるようになります。通知はブラウザ通知・デスクトップアプリのOS通知のほか、Focus以上ではSlackへ通知を送ったり、指定Slackチャンネルの会話からAIが1日1回ゴール候補を提案するアンビエント連携も備えます（連携仕様）。

1-5. ナレッジ・AIドライブ・議事録・画面録画がAIの文脈になる仕組み

  • ナレッジとテンプレートの役割分担：テンプレート・ルーティンFAQによると、「ナレッジ」は組織で使い回す個別手順（やり方）の置き場であり、AIは仕事開始時にナレッジを探し、終了時に残す価値のあるやり方を書き残すようAddness側から指示されています。一方「テンプレート」は、ツリー構造・理想・メモ・コメント・リソース一式を複製できるゴールツリーの雛形です。
  • AIドライブ：AIドライブはゴールのリソース、議事録、画面録画、直接アップロードしたファイル（1ファイル50MB・一度に100件まで）を一元管理します。ゴールに紐づくリソースはそのゴールの閲覧権限を自動継承し、MCP連携したAIは依頼者が閲覧権限を持つ範囲から名前・タグ・フォルダ・ゴールで検索し、テキスト系ファイルは本文まで読んで回答します。
  • Meet・Zoom議事録Bot / ハドル / 対面会議：議事録機能では、Google Meet・ZoomにURL指定またはChrome拡張「Addness Meet Recorder」でBotを参加させるほか、Addness内のハドル通話やPCを置いた対面会議でも文字起こし（日・英・越対応、最大50名）とAI要約を生成します（Microsoft Teamsは非対応）。生成された議事録はMarkdownとしてゴールのリソースに入り、AIが読んで「誰が・何を・いつまで」のToDoへ分解できます。
  • 画面録画・文字起こし：Pro以上で月3本、Focusで月300本、Unlimitedで無制限に画面と声を録画し、文字起こし（Focus以上）とあわせてゴールの手順・背景リソースとして蓄積できます（料金プラン比較表）。

1-6. KPIツリー・アナリティクス・活用レポート・CRM・DB/フォーム

アナリティクス（Beta）は「ダッシュボード（ウィジェット表示）」「KPI定義（数え方・取得元・更新契約）」「集計済みデータベース（取得元からAIが収集した材料）」の3層で構成されます。ダッシュボード自体はAIでなくGUIで組むのではなくClaude Code等からMCPで作成する前提となっており、子KPIが更新されると親KPIの達成率や月末着地見込みが自動連動します。朝の定期更新が失敗すると赤い帯で「走らなかった／失敗／実行中のまま／数字欠け」の内訳が出て、「この定義をアドる」からそのままAIに修復を依頼できます（ダッシュボード一覧50件、Daily表示1年、ゴール紐づけKPI 500件の上限あり）。

活用レポートはFocusプランで「概要」、Unlimitedプランで「全部＋CSV（メンバー・チーム・機能・AIの詳細、CSV出力）」が提供されますが、具体的な指標項目の完全な一覧は公開ページ上で確認できませんでした（料金ページ）。AddnessCRMは全プランに含まれ、顧客情報とやり取りを案件ゴールへ紐づけますが、CRM単体の詳細仕様ページや提案資料で言及されている「フォーム」単体の詳細動作についても、公開Web上の一次情報では確認できませんでした。

2-1. リモートMCPと読み書き権限・確認フロー

リモートMCPサーバー（https://vt.api.addness.com/mcp）は、Claude Code では claude mcp add --transport http --scope user addness https://vt.api.addness.com/mcp と claude mcp login addness で導入でき、Cursor では ~/.cursor/mcp.json、Claude Desktop ではカスタムコネクタとして登録します（Addness MCP、Cursor設定、Claude設定）。

AIができる操作は、ゴールの読み書き（作成・更新・完了）、今やるべきToDoの確認、進捗・アクティビティ把握、コメント投稿・通知処理、成果物の登録、ゴール検索です。重要な点として、AIが見られる範囲は「OAuthでログインしたユーザー本人がAddness上で閲覧権限を持つ範囲」に厳格に限定されます。アサインされていないゴールや他組織データは参照できず、管理者がメンバーを組織から外すとその人のAIからのアクセスも即座に遮断されます（セキュリティページ）。なお、書き込み時の確認フローについては、ChatGPT公式プラグインでは「ゴールの作成・更新・完了など書き込む前にChatGPT画面に確認が出る」と公式プレスリリースに明記されています。一方、Claude Code等の汎用MCPクライアントにおける書き込み承認UIは各クライアント側のツール実行承認設定に依存します。

2-2. 公式対応AIとその他MCPクライアントの接続可否

公式が設定ガイドや対応を明記しているのはClaude Code、Codex、Cursor、Claude Desktop、ChatGPT（公式プラグイン）の5つ（加えてCLIページでGitHub Copilot連携を例示）です。これら以外についても、公式ページでは「MCP対応のAIエージェントなら、どれでもAddnessに接続できます」と表明されています（Addness MCP）。ただし、独自のチャットツールやWebサービスがStreamable HTTP＋OAuthのリモートMCPに対応していない場合は直接接続できず、後述するCLI経由またはプロンプト橋渡しが必要になります。

2-3. Addness CLI と Desktopアプリの補足

Addness CLI（2026年3月公開ページ確認）は、ターミナルから addness goals list --json や addness comments create で操作でき、addness skills コマンドで CLAUDE.md 等に貼れるAI向けコマンド定義を出力できます。またDesktopアプリは、個人のLINE（Pro以上でグループLINEのAddyも利用可）やFacebook MessengerをローカルPC経由でAddness MCPにつなぐ機能（履歴はクラウドに複製せずローカル保持）や、グローバルショートカット・音声入力を備えますが、Windows版は未署名のためSmartScreenの警告が出ることがあり、会社PCでは実行できない場合があると公式に注意書きされています。

3-1. 個人利用・人数カウント・教育事業との関係・総コスト

  • 1人から利用可能・最低人数・初期費用なし：法人向け色が強いものの「1人から使える」と明記されており、初期費用は公式ページ上確認されません（料金ページ）。
  • AIエージェントは人数に数えない：課金対象は人間のメンバーのみ。ゲスト（閲覧・コメント・チャットのみ）や他組織で課金済みの外部メンバー、さらにMCPでつないだAIエージェントは何体いても無料です。
  • AI利用料は別契約（総コストの考え方）：Addnessの料金にはAIモデルの利用料が含まれません。公式FAQでは「Claude Codeを使う人はClaude Pro（月$20〜）、Codexを使う人はChatGPT Plusから始めれば十分」と案内されています。したがって個人でStarter（$4.99）＋Claude Pro（$20）を使う場合、総コストは月額約$25（約3,900〜4,000円前後）〜となります。すでにAI契約を持っている個人エンジニアであれば、追加コストはAddnessの月額（最安$4.99）のみです。
  • 教育事業との関係と留意点：アドネス株式会社は社会人向けオンラインスクール「スキルプラス」や「AIラボ」も運営しており、受講生向けの専用クーポンが存在することが公式FAQに明記されています。なお、同社の教育・電話勧誘販売事業をめぐっては2025年12月に消費者庁から特定商取引法に基づく「指示」の行政処分を受けた公表事実（消費者庁PDF）がありますが、業務停止命令ではなく、AddnessというSaaS自体の技術仕様・セキュリティとは切り離して評価すべき点です。

（Stateは貯めずKnowledgeは貯める）		 ゴールツリー（Goal）、進捗・現在地（State）、ナレッジ/テンプレート（Knowledge） 自前でもディレクトリ分離で再現済み。Addnessでは「完了は翌日午前4時に消え、やり方はナレッジに残る」UIが組み込み済み。
ゴールツリーと差分駆動
（全部描かず次の関門だけ足す）		 4ステップ分解UI＋「今やるべきToDo」への手動選定＋「アドる」 Markdownは一覧性やドラッグ操作・期日バッジ・KPIリング連動で劣る。一方、テキスト編集の速さはMarkdownが上。
経営（意図）と執行（実行）の分離
（人は意図を決め、AIがやり抜く）		 人は「理想」と「OK出し」、AIが分解・実行・書戻し 設計思想自体は自前でも完全に一致。Addnessは「他人のAI」と接続して仕事を渡せる点が異なる。

5. 現行の個人マルチAI構成への導入効果（核心）

ここからは、すでに以下の構成を自前で構築・運用している個人ITエンジニアの環境を前提に、Addnessを導入する実質的な効果を検証します。

前提とする現行の個人マルチAI構成（一般化）

  • パーソナルエージェント（チャット型）：記憶・目標管理・定期実行ジョブ（朝の確認、週次レポート、各種監視）・他AIへの指示出しを担う司令塔。
  • 実装エージェント（自宅PC上）：コード実装やファイル生成を担い、チケット形式の「引き継ぎ」ファイルで指示を受ける。
  • 調査用AI（Webチャット型）：ファイル経由のリクエストチャネルで調査・文書作成を担う。
  • 共有基盤：Gitリポジトリ＋クラウドドライブの二重同期。目標・状態・知識はMarkdown群とパーソナルエージェント側のゴール管理UIで保持。

5-1. Addnessを入れると「新しくできるようになること」

  1. ゴールツリーとKPI数値（達成率リング・着地見込み）の一体管理：Markdownの階層リストでは実現しにくい「親ゴールと子ゴールの構造＋KPI達成率の視覚的連動＋AIによる毎朝データ更新と停止検知」が標準で手に入ります。
  2. 「アドる」によるワンクリック文脈渡し：現在のようにチケット形式の引き継ぎファイルを起票・同期しなくても、ゴール行の「アドる → 進める」からClaude CodeやCodexをプロンプト入力済みで即起動でき、作業後の進捗・成果物リンクもMCP経由でそのままゴールへ書き戻せます。
  3. チャット＝コメントによる文脈の自動蓄積とスマホ確認：Git上のMarkdownをスマホから編集・確認するのは手間がかかりますが、AddnessにはiOS/AndroidアプリとブラウザUIがあり、外出先から「今やるべきToDo」の確認やゴールチャットへの指示メモ残しが容易になります。
  4. PC経由LINE・議事録・画面録画の文脈統合（Pro以上）：自宅PCのDesktopアプリを使えば個人LINEのやり取りをMCP経由でAIに読ませたり、会議や操作手順の録画を直接ゴールに紐づけられます。

5-2. 現行構成と重複する部分・置き換わる部分

すでに自前実装済みの「Goal / State / Knowledge の記憶管理」「引き継ぎチケットによる実装エージェントへの指示出し」「ゴール管理UI」はAddnessと機能的に大きく重複します。もしAddnessへ寄せる場合、ゴール管理と引き継ぎチケットの役割はAddnessのゴールツリー＋コメント＋AIメモリに置き換えられます。

逆に、「朝の確認や各種監視を行う定期実行ジョブ（司令塔）」「Gitによるコード・成果物の厳密なバージョン管理とローカル完結のファイル連携」はAddness単体では代替できません（Addnessのルーティンは定型ToDoを今日に並べる機能であり、自律的な監視バッチ実行エンジンではありません）。

5-3. 現行の各エージェントはAddnessにつながるか（接続の現実性）

現行エージェント Addness接続の現実性 接続ルートと制約・注意点
実装エージェント（自宅PC上） 直結可能（高） Claude Code / Codex / Cursor 等であれば https://vt.api.addness.com/mcp（OAuth）または Addness CLI で即座に読み書き可能。
調査用AI（Webチャット型） 環境依存（中） ChatGPTなら公式プラグイン、Claudeならカスタムコネクタで接続可。一方、それ以外のWebチャットAIや独自ファイル監視チャネルを使う場合はMCP非対応の可能性があるため、従来通りファイル経由の橋渡しが必要（公式で未確認のクライアントは不可前提で設計すべき）。
パーソナルエージェント（司令塔・定期ジョブ） 要確認（低〜中） お使いのパーソナルエージェントが外部リモートMCP（Streamable HTTP + OAuth）またはローカルシェル実行（Addness CLI）に対応していれば接続可能。非対応のクローズドなチャット型エージェントの場合、Addnessと直接同期できないため二重管理の温床になる。

5-4. 共存設計の現実的な2パターン

全面移行ではなく、現行の「司令塔＋Git/ドライブ基盤」の強みを活かした段階的共存設計としては、次の2案が現実的です。

  • 案A：ゴールツリー＆引き継ぎハブ限定導入（Starter $4.99/月）
    Markdownの「ゴール管理・引き継ぎチケット」部分だけをAddnessのゴールツリーへ移し、自宅PCの実装エージェントをMCP接続する。コードや成果物ファイルの実体は従来通りGit＋クラウドドライブに置き、Addnessのゴールには「成果物パス／URL」と「決定事項」だけを書戻す。司令塔や調査用AIがMCP非対応でも、人がスマホやブラウザで「アドる」起点のディレクションを行えるため破綻しにくい。
  • 案B：ハイブリッド運用（CLI + Gitフック連携）
    自宅PC上の Addness CLI（--json）を定期スクリプトや実装エージェントから叩き、Git側の目標・状態ファイルとAddness側を同期させる構成。ただしAPI/CLIの仕様変更追従や同期バグの保守コストが発生するため、個人の省力化目的とは相反するリスクがある。

5-5. リスクと制約（個人ITエンジニア視点）

導入前に押さえるべき5つの制約

  1. Freeプラン廃止による固定費：2026年11月16日のFree終了により、維持だけで最低月額$4.99（機能フル活用なら$19〜$39）が発生します。
  2. 法人向け機能の余剰と「スマホ完結不可」：公式も「スマホだけで完結させたい場合は向いていない（AIアプリを動かすPCが必要）」と明記しています。またCRMや会議Bot・活用レポート等は個人開発では持て余しやすい機能です。
  3. データ主権とベンダーロックイン：Git＋Markdownであればローカルに全テキストが残り、いつでも任意のエージェントやツールへ移行できますが、Addness中心にすると状態・会話・AIメモリがクラウドSaaS（AWS東京リージョン＋一部米国外部処理）側に寄ります。なお解約してもデータは削除されず再契約で再開可能ですが、契約停止中は閲覧・MCP利用ができなくなります。
  4. 二重管理の危険：パーソナルエージェント側のゴール管理UIとAddnessのゴールツリーの両方を生かすと、どちらが正本か分からなくなり確実に運用が崩れます。導入するなら「ゴールの正本はどちらか一方」に決める必要があります。
  5. セキュリティ認証とOS制約：ISMS・SOC 2等の第三者認証は現時点で未取得（チェックシート個別対応）。またWindows版Desktopアプリは未署名のためSmartScreen警告が出る場合があります。

6. 結論：判断基準と導入する場合の最初の一歩

「思想は導入済み、製品は未導入」の個人ITエンジニアにとって、Addnessは必須のインフラではなく、UI・文脈接続の快適さを買うオプションツールです。

判断の軸 Addnessを入れる価値がある条件 現行の自前構成で足りる条件
運用UI・スマホ操作 MarkdownやGit操作を離れ、スマホやブラウザでゴールツリーとKPI達成率を直感的に見たい。 現在のパーソナルエージェントUIとMarkdown一覧で視認性・操作性に不満がない。
AIへの指示出し Claude Code / Codex / Cursor / ChatGPT間を「アドる」一発でシームレスに引き継ぎたい。 引き継ぎファイル起票＋ドライブ同期の現行フローでストレスを感じていない。
データ主権・自由度 月$4.99〜$19のSaaS課金を許容でき、将来的なチーム/外注への展開も視野に入れている。 全データのローカル/Git完結と、定期ジョブ司令塔による完全自動化・無料維持を重視したい。

導入を検討する場合の「最初の一歩」（最小検証ステップ）

もし「実際の使用感で判断したい」という場合は、いきなりPro以上や全面移行へ進まず、以下の手順で1週間・$4.99の検証を行うのが最も合理的です。

  1. Starterプラン（$4.99/月・1人組織）で登録する：無料トライアルは付きませんが、解約すれば翌月以降は課金されません。まずは最も安い構成でゴールツリーとMCPだけを評価します。
  2. 進行中の1プロジェクトだけゴールツリーに置く：大目標と「理想」、最初の関門2〜3個だけを書き、既存Gitにある全てのタスクは移しません。
  3. 自宅PCの実装エージェントにMCPを繋ぐ：https://vt.api.addness.com/mcp を設定し、OAuthでログイン。Addness画面の「アドる → 進める」から実装エージェントを起動し、「今の引き継ぎチケット運用と比べて本当に速く・楽になるか」を3〜5回試して最終判断します。

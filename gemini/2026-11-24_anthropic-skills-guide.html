Section 01

導入：Agent Skillsとは何か

Agent Skills は、AIエージェントに特定タスクの専門手順・知識・実行スクリプトをパッケージ化して渡すための軽量なオープンフォーマットです。中核となるのは SKILL.md という1つのMarkdownファイル（先頭にYAMLフロントマターで name と description を記述）を含むフォルダ構成であり、必要に応じて scripts/（実行コード）、references/（判断基準資料）、assets/（テンプレート）を同梱します。 

my-skill/
├── SKILL.md       # 必須：YAMLフロントマター（name, description）＋ Markdown手順
├── scripts/       # 任意：Python / Node.js 等の実行スクリプト
├── references/    # 任意：詳細ガイドラインやルールブック
└── assets/        # 任意：テンプレートやフォント等の静的リソース

1. 段階的開示（オンデマンド読込）

起動時は各スキルの name と description（約100トークン程度）だけを常駐させ、依頼に合致した時だけ SKILL.md 本文やスクリプトを読み込みます。そのため、多数のスキルを導入してもコンテキストを圧迫しにくい設計です。

2. オープン標準化とAAIF寄贈

2025年10月にClaude Codeの機能として始まり、2025年12月にオープン標準として公開されました。さらに2026年10月22日にはLinux Foundation傘下の Agentic AI Foundation（AAIF） へ寄贈され、業界標準として管理されています。

3. Claude以外のAIでも利用可能

オープン標準化により、Claude（Claude.ai / Claude Code / Claude API）だけでなく、OpenAI（ChatGPT / Codex CLI）、Google（Gemini CLI）、Cursor、GitHub Copilot、VS Code など70以上のエージェント環境で同じ SKILL.md 資産を活用できます。

プラグイン構成の補足： 公式リポジトリ anthropics/skills の .claude-plugin/marketplace.json では、19スキルが5つのプラグイン（document-skills 4種、example-skills 12種、単独プラグインの claude-api / academy-guide / discernment-nudge）として配布されています。

Section 03

スキル別詳細解説（全19種）

各スキルの SKILL.md および公式定義から読み取れる機能、適用場面、設計上の要点をまとめています。

ドキュメント作成系（Document Skills）

Word・PDF・PowerPoint・Excelの実務ファイルを生成・編集・検証する4つの基盤スキルです。

docx

ドキュメント作成系

Plugin: document-skills · SKILL.md を見る ↗

概要

Word文書（.docx）をゼロから生成し、既存文書の編集・テキスト抽出・変更履歴（Tracked Changes）やコメントの挿入まで一貫して扱うドキュメントスキルです。

できること
  • docx（npm / docx-js）を用いたA4/US Letter対応の新規.docx生成（表・画像・目次・ヘッダー/フッター・脚注対応）
  • 既存.docxのZIP展開（unpack）→ word/document.xml直接編集 → 再圧縮（zip）によるレイアウト維持編集
  • pandocによるMarkdown形式でのテキスト読取、およびLibreOfficeによるレガシー.docの変換
  • w:ins / w:del タグによる変更履歴（赤入れ）と comment.py を用いたコメントスレッドの付与
使う場面

社内報告書・契約書・仕様書をWord形式で納品したいとき、または既存のWordファイルに書式を崩さず修正やレビューコメントを入れたいときに使います。

向いているユーザー

法務・管理部門、コンサルタント、ビジネス文書や契約書の作成・レビューをAIに任せたい実務者

SKILL.md の中身の要点
  • 新規作成は docx-js、既存編集は XMLアンパック方式とタスク別に明確にアプローチを分離
  • 表のセル幅はDXA単位で指定（Google Docs互換のためPERCENTAGE禁止）、背景網掛けはShadingType.CLEARを指定などの落とし穴を明記
  • merge_runs.py で分割された <w:r> タグを統合し、validate.py でXSDスキーマ検証を実施
  • 生成後は LibreOffice（soffice.py）→ PDF化 → pdftoppm で画像化し、視覚的崩れを目視確認する工程を必須化

pdf

ドキュメント作成系

Plugin: document-skills · SKILL.md を見る ↗

概要

PythonライブラリとCLIツールを使い分け、PDFのテキスト・テーブル抽出からReportLabによる新規PDF作成、結合・分割・回転・透かし・パスワード保護・OCR・フォーム入力までを統合的に扱います。

できること
  • pdfplumber によるレイアウト保持テキスト抽出およびテーブル抽出（pandas連携でExcel化も可能）
  • pypdf / qpdf / pdftk によるPDFの結合、ページ分割、回転、メタデータ取得、暗号化・透かし付与
  • reportlab（Canvas / Platypus）を用いた複数ページPDFや図表入りレポートのプログラム生成
  • pytesseract + pdf2image によるスキャンPDFのOCR処理、および FORMS.md に基づくAcroForm/XFAフォーム入力
使う場面

請求書や論文PDFから表データを抜きたいとき、複数PDFを1つにまとめたいとき、または帳票・レポートを印刷用PDFとして生成したいときに使います。

向いているユーザー

バックオフィス担当者、データアナリスト、大量のPDF資料・申請書を扱うすべてのユーザー

SKILL.md の中身の要点
  • 用途別の最適ツール早見表（抽出=pdfplumber、作成=reportlab、結合=pypdf/qpdf、OCR=pytesseract）を提示
  • ReportLabでUnicodeの下付き/上付き文字を使うと黒四角に文字化けするため、<sub> / <super> XMLタグを使うよう厳密に注意喚起
  • フォーム入力手順は FORMS.md、高度なpypdfium2/pdf-lib解説は REFERENCE.md へ分離し、オンデマンド読込に対応

pptx

ドキュメント作成系

Plugin: document-skills · SKILL.md を見る ↗

概要

pptxgenjs によるプレゼンテーションの新規作成と、既存 .pptx / .potx テンプレートのXML編集によるスライド生成・更新を行い、視覚的QAまで徹底するスキルです。

できること
  • pptxgenjs を用いた16:9 / ワイド画面のスライド生成、ネイティブチャート（addChart）・アイコン（react-icons→PNG化）・スピーカーノート挿入
  • thumbnail.py でテンプレートの全スライド一覧グリッド画像を作成し、適切なレイアウトを選定
  • add_slide.py / clean.py / validate.py を用いたスライド複製・削除・孤立リソース整理・OOXML検証
  • markitdown によるテキスト・ノート抽出、および LibreOffice + pdftoppm による全スライド画像化QA
使う場面

企画書やピッチデックをゼロから作りたいとき、または会社の公式PowerPointテンプレートに沿って複数スライドを自動生成したいときに使います。

向いているユーザー

営業・企画職、経営層向け資料作成者、定例報告や提案スライドを効率化したいチーム

SKILL.md の中身の要点
  • 色設計は「1つの主色が60〜70%の視覚的重み」を原則とし、タイトル下の装飾線やカードの端のカラーバーなど「AIっぽい装飾」を明確に禁止
  • pptxgenjsの落とし穴（色コードに#を付けない、オプションオブジェクトを使い回さない、stacked barのdataLabelPosition制約等）を網羅
  • LibreOfficeでのフォント置換による文字はみ出し誤判定を防ぐため、安全フォント（Arial, Calibri, Cambria等）と非推奨フォント（Aptos等）を明記

xlsx

ドキュメント作成系

Plugin: document-skills · SKILL.md を見る ↗

概要

openpyxl と pandas を使い分け、動的数式や財務モデリング規約に準拠したExcelブックの作成・編集・クレンジング・再計算検証を行うスキルです。

できること
  • openpyxl を用いた数式・条件付き書式・セル配色・表示形式付きの本格的なExcelブック作成
  • pandas による大容量表データの高速読込・クレンジング・変換、および markitdown によるシート構造の素早い把握
  • scripts/recalc.py（LibreOffice連携）を用いた全数式の再計算キャッシュ生成とエラー（#REF!, #DIV/0!, #NAME?等）のゼロ検証
  • 財務モデル標準のカラーコーディング（青=手入力、黒=数式、緑=他シート参照、赤=外部リンク、黄塗=主要前提）の自動適用
使う場面

予算表・売上予測・財務モデルなど「入力値を変えれば再計算されるExcel」を作りたいとき、または乱雑なCSV/Excelを整形したいときに使います。

向いているユーザー

経理・財務・経営企画担当者、データ分析者、スプレッドシート業務を自動化したいビジネスパーソン

SKILL.md の中身の要点
  • 「計算結果のベタ打ち禁止・必ずExcel数式（=SUM()等）を書く」ことを絶対ルール化
  • LibreOfficeで #NAME? になる XLOOKUP / FILTER / UNIQUE 等を禁止し、INDEX/MATCH や Excel 2007互換関数（または _xlfn. プレフィックス）を推奨
  • openpyxl の data_only=True 読込後に保存すると数式が消える罠や、外部リンク消失への警告を詳細に記載

デザイン・クリエイティブ系（Creative & Design）

ジェネラティブアート、ポスター、Slack用GIF、テーマ適用、ブランド統一、フロントエンドUI設計を担う6スキルです。

algorithmic-art

デザイン・クリエイティブ系

Plugin: example-skills · SKILL.md を見る ↗

概要

まず「アルゴリズム哲学（.md）」を宣言してから、その思想を p5.js のコード（単一HTMLビューア）として具現化する2段階のクリエイティブコーディングスキルです。

できること
  • Organic Turbulence や Quantum Harmonics のような計算美学のマニフェスト（4〜6段落の.md）の作成
  • templates/viewer.html を土台とした、シード値ナビゲーション（Prev/Next/Random/Jump）付きの単一HTMLアーティファクト生成
  • パーリンノイズ・フローフィールド・パーティクル・再帰分割などをパラメータスライダーでリアルタイム調整できるUI構築
  • 同一シードによる完全な再現性（randomSeed / noiseSeed）とPNGダウンロード機能の実装
使う場面

壁紙・イベントビジュアル・アート作品として、パラメータを変えて何通りも試せるコードベースのアートを作りたいときに使います。

向いているユーザー

クリエイティブコーダー、ジェネラティブアートに関心のあるデザイナー、Web上で動くアート実験をしたい人

SKILL.md の中身の要点
  • 静止画テンプレートではなく「生きたアルゴリズム（90%が計算生成、10%が調整可能パラメータ）」であることを強調
  • STEP 0 として templates/viewer.html を必ず先に読み込み、AnthropicブランドのサイドバーUI（Seed→Parameters→Actions）を維持するよう厳格に指示
  • p5.jsはCDN経由で読み込みつつ、それ以外のJS/CSSをすべて1つのHTMLファイルにインライン化する構成

デザイン・クリエイティブ系

概要

コードベースのアートではなく、空間・余白・色彩・タイポグラフィを重視した「90%ビジュアル・10%最小限テキスト」の静止画アート（.png / .pdf）を2段階で制作するスキルです。

  • 要望に応じた複数ページ（コーヒーテーブルブック風）のPDFシリーズ展開と2パス目の磨き込み（Refinement）
使う場面

イベントポスター、表紙グラフィック、抽象的なコンセプトビジュアルなど、文字説明に頼らない洗練された一枚絵を作りたいときに使います。

向いているユーザー

グラフィックデザイナー、イベント企画者、プレゼン表紙やSNS用の洗練されたビジュアルが欲しい人

SKILL.md の中身の要点
  • 特定アーティストの作風模倣を避けつつ、反復パターン・余白・極小の臨床的ラベルで「人間が何時間もかけて仕上げたような工芸品品質」を要求
  • Final Step で「新しい要素を足すな、既存の構成を研ぎ澄ませ（2パス目）」と自己批評・洗練プロセスを組み込んでいる点が特徴

slack-gif-creator

デザイン・クリエイティブ系

Plugin: example-skills · SKILL.md を見る ↗

概要

Slackのファイルサイズ・解像度・フレームレート制約に合わせて、Python（Pillow / imageio / numpy）と内蔵ユーティリティで滑らかなGIFアニメを作成するスキルです。

できること
  • 絵文字用（128×128、3秒以内）およびメッセージ用（480×480）のSlack規定サイズでのGIF生成
  • core.gif_builder（GIFBuilder）によるフレーム組み立て、色数削減（48〜128色）、重複フレーム除去による軽量化
  • core.easing の7種イージング関数（bounce_out, elastic_out, back_out等）を使った滑らかな動き
  • core.validators（validate_gif / is_slack_ready）によるSlack適合性の自動チェック
使う場面

チームのSlackで使うオリジナル絵文字や、お祝い・リアクション用の軽量アニメーションGIFを素早く作りたいときに使います。

向いているユーザー

開発チーム・コミュニティ運営者、Slackのリアクション文化を盛り上げたいメンバー

SKILL.md の中身の要点
  • Shake、Pulse、Bounce、Spin、Fade、Slide、Zoom、Particle Burst の8つの基本アニメーション設計パターンを解説
  • 環境依存で崩れる絵文字フォントの使用を禁止し、太めの線（width>=2）やグラデーション・ハイライトを重ねたPILプリミティブ描画を推奨
  • ユーザーが画像をアップロードした場合は、それを直接アニメ化するか着想元として扱うかを柔軟に判断

theme-factory

デザイン・クリエイティブ系

Plugin: example-skills · SKILL.md を見る ↗

概要

スライド、ドキュメント、HTMLレポートなどあらゆる成果物に対し、厳選された10種類のプリセットテーマ（カラーパレット＋フォントペアリング）または即席のカスタムテーマを適用するスキルです。

カテゴリ別の使い分けと相乗効果

  • ドキュメント作成系（4種）: 「数式・XML検証・画像化目視QA」を組み込んだ実務エンジン。doc-coauthoring で構成を練り、docx や pptx で仕上げる連携が強力です。
  • デザイン・クリエイティブ系（6種）: 実装前に「哲学（.md）」や「テーマ」を宣言させることで、AI特有の画一的な出力（AIスロップ）を防ぎます。
  • 開発・技術支援系（5種）: skill-creator でスキルを育て、webapp-testing で実ブラウザ検証を回す「自己検証ループ」の構築に適しています。
  • 回答ガイダンス系（2種）: 成果物ではなく「回答の振る舞い」を補正するメタ的なスキル。常駐トークンと自動発火のバランスを見ながら導入します。

公式スキルに共通する設計パターン

  • スクリプトのブラックボックス実行: 複雑な処理（recalc.py や with_server.py）はAIにコードを読ませずコマンド実行させ、コンテキストを節約しています。
  • 「やらないこと（抑制条件）」の明記: discernment-nudge や academy-guide に見られる通り、発動条件以上に「いつ黙るか」を細かく定義することで実務の邪魔を防いでいます。
  • 視覚・構造バリデーションの必須化: 出力して終わりではなく、validate.py や LibreOffice→画像化チェックをワークフローに強制しています。

Claude以外（ChatGPT / Codex / Gemini等）での活用

SKILL.md はオープン仕様（agentskills.io）であるため、他社エージェントでもそのまま再利用できます。ただし移植性を高めるには以下の点に注意が必要です。

  • 配置ディレクトリの違い: Codex CLI・Gemini CLI・Cursor・GitHub Copilot は共通の .agents/skills/ を参照します（Claude Code は .claude/skills/ を参照）。両方で使う場合はシンボリックリンク等で共有すると管理が容易です。
  • フロントマターを標準6項目に限定: 必須の name（64字以内）・description（1,024字以内）と、任意の license / compatibility / metadata / allowed-tools に留めると、他ツールや skills-ref 検証でエラーになりません。

導入時の運用・セキュリティ上の注意

  • 常駐トークンの意識: セッション開始時に読み込まれるのは description です。自動発動型スキルを大量に入れると常駐トークン（19種合計で約3,360トークン目安）が増えるため、使わないプラグインは無効化しておくと軽快です。
  • 外部スキルの事前確認: スキルはエージェントの実行権限（コマンド実行やファイル読取）をそのまま継承します。第三者製スキルを導入する際は、必ず事前に SKILL.md と scripts/ の中身を確認してください。

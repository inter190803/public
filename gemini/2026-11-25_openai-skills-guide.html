1. 導入：OpenAIの「Skills Catalog」と SKILL.md オープン標準

SECTION 01

openai/skills は、OpenAIのコーディングエージェント Codex（Codex CLI / Codex App / IDE拡張） 向けに公式公開された「Skills Catalog（スキルカタログ）」リポジトリです。Anthropicが提唱しオープン標準（Agent Skills Specification）となった SKILL.md 形式 を採用しており、AIエージェントを汎用アシスタントから「特定ドメインの専門作業を安定して遂行するスペシャリスト」へと拡張する再利用可能なワークフローパッケージを提供します。

重要：リポジトリのDeprecation（非推奨化）と openai/plugins への移行について

openai/skills のルート README.md には現在、「This repository is deprecated. For current Codex skill and plugin examples, use the OpenAI Plugins repository.」 という公式バナーが掲出されています（2026年6月〜7月のコミットで移行案内を追加）。
これは「スキルという仕組みが廃止された」のではなく、配布の単位が「単体のスキルフォルダ」から「スキル・MCPサーバー（.mcp.json）・エージェント・フックを束ねるプラグインマニフェスト（.codex-plugin/plugin.json）」へと昇格・統合されたことを意味します。既存の SKILL.md はそのまま動作し、プリインストールされている $plugin-creator スキルを使えば既存のスキルフォルダを「Skill-only plugin」として現行のプラグイン形式へ即座にラップできます。また、本リポジトリにはルート直下の共通 LICENSE ファイルがなく、各スキルのディレクトリ内の LICENSE.txt（Apache-2.0 または Figma Developer Terms 等）で個別にライセンスが規定されている点も実務上の重要ポイントです。

① 段階的開示（Progressive Disclosure）

セッション起動時は各スキルのYAMLフロントマター（name と description）のみを読み込み、ユーザーの依頼が合致したとき（または $skill-name / /skills で明示呼び出しされたとき）だけ SKILL.md 本文をロードします。さらに詳細なAPI仕様や言語別ルールは references/ 配下に1階層で分離され、必要な瞬間までトークンを消費しません。

② OpenAI独自の5要素解剖学

OpenAI公式スキルは、(1) 作業手順の中核を定義する SKILL.md、(2) Codex UIでの表示名・短い説明・既定プロンプト・アイコンを定義する agents/openai.yaml、(3) 検証やAPI呼び出しを担う決定論的コード scripts/、(4) 必要時に引く技術資料 references/、(5) 最終成果物に使うテンプレートやヘルパー部品 assets/ の5要素で構成されます。

③ カタログの収録件数とスナップショットの整理

本リポジトリは skills/.system（Codexに自動プリインストールされる 5件）と skills/.curated（$skill-installer <name> で導入する公式キュレーション群）の2層構造です（READMEに記載のあった .experimental/create-plan は後に削除）。.curated は最終HEAD時点で 38件（.system 5件と合わせて43件）、2026年春〜初夏の変遷の中でプラグイン側やビルトインへ整理された旧版 6件（doc, slides, spreadsheet, sora, frontend-skill, develop-web-game）を含めると 計44件 が存在します。本ガイドでは漏れを防ぐため、全44件の .curated スキル＋全5件の .system スキル（合計49件）をすべて一次情報に基づき完全解説します。

5.1 Anthropic公式スキル（anthropics/skills）との共通点と決定的な違い

5.2 Claude Code / Gemini CLI・Antigravity / GitHub Copilot で OpenAI のスキルを使う方法

openai/skills に収録されている各スキルは標準の SKILL.md 形式で書かれているため、Codex専用メタデータである agents/openai.yaml は他エージェントでは安全に無視され、フォルダを各エージェントのスキルディレクトリへ配置するだけでそのまま活用可能です。

Claude Code で使う場合

プロジェクト単位なら .claude/skills/<skill-name>/、全プロジェクト共通なら ~/.claude/skills/<skill-name>/ にスキルフォルダ（SKILL.md と同梱の scripts/, references/, assets/）をコピーします。npx skills add openai/skills --agent=claude-code でも選択導入が可能です。なお $CODEX_HOME 環境変数を参照するスクリプト（playwright や transcribe 等）を使う場合は、パスを ~/.claude/skills/ に読み替えるか環境変数 CODEX_HOME=~/.claude を設定するとスムーズに動作します。

Gemini CLI / Antigravity で使う場合

ワークスペース共有なら .agents/skills/<skill-name>/（または .gemini/skills/）、個人グローバルなら ~/.gemini/skills/（または ~/.agents/skills/）へ配置します。コマンド1行で入れる場合は npx skills add openai/skills --agent=antigravity または gemini skills install https://github.com/openai/skills.git --path skills/.curated/<skill-name> が利用でき、対話中は /skills list や /skills reload で即座に認識されます。

GitHub Copilot (VS Code / CLI) で使う場合

リポジトリ内の .github/skills/<skill-name>/SKILL.md にフォルダを配置すると、VS Code Copilot および GitHub Copilot CLI がワークスペーススキャンで自動検出します。複数エージェントを併用するリポジトリでは、実体を .agents/skills/ や .github/skills/ に1つ置き、.claude/skills/ 等へシンボリックリンク（ln -s）を張ることで重複管理を防げます。

経営・情シス・現場リーダーが最初に押さえるべき4つの核心
  • 「人件費並みに跳ね上がるか？」への答え： 適切な支出ポリシー（Spending Policy）と業務設計があれば、通常運用は 月額$70〜$180（約1万〜2.7万円/体、固定費込） 程度で収まり、人件費の数十分の1のROIが見込めます。しかし、高頻度ポーリングのルーチンを上限なしで放置すると月$1,000〜$2,000超（若手社員1名分の人件費級）へ青天井化する構造リスクが確実に存在します。
  • 「個人秘書型か、チーム社員型か？」への答え： 技術・契約仕様は明確に「1人の責任者（Named Manager）に紐づく個人専用（1:1）」であり、共有架空アカウント運用は非推奨です。ただしTeamsチャネルで同僚が `@mention` して業務を振れるため、実務上の最適解は「リーダー／PMを責任者とする1体を『個人秘書兼チームPMO』としてチャネル常駐させるハイブリッド運用」です。
  • 管理者セキュリティの最大の罠： プレビュー現時点では「条件付きアクセス（All users）の対象外」「eDiscovery・訴訟ホールド・保持ポリシー未対応」「秘密度ラベルの自動継承保証なし」「Memoryオフ不可」「ブロック反映に約1時間遅延」という重大なコンプライアンス制約があります。法務・機密部門への早期展開は厳禁です。
  • 育成（オンボーディング）の本質： プロンプト1発で完結させるツールではなく、「下書き専用フェーズ → 3層メモリの定期矯正 → `SKILL.md` による業務手順のスキル化と社内共有 → 段階的な自律実行」と、まさに新入社員をOJTで育てるアプローチが成果を分けます。

Copilot Autopilot は、2026年6月の Microsoft Build で「Scout」として披露され、2026年9月25日の Copilot 大刷新（Home / Cowork / Code / Autopilot の再編）を経て、2026年11月17日の Microsoft Ignite 2026 より Frontier プログラム対象顧客向けにロールアウトが開始された、クラウド常駐型のプロアクティブ自律AIエージェントです（Microsoft Learn Overview、Aithoria解説）。

名称混同の注意（ヘルプデスク対策）： 情シスが長年PCキッティングに使用してきた Intune の Windows Autopilot とは名前が同じだけで完全に別製品です（WindowsForum報道）。また、旧デスクトッププレビュー（Scout時代）のローカルインストール手順は現行クラウド版には適用されません（Requirements）。

構成要素 公式仕様・技術詳細（2026年11月 Frontier版）
独自アイデンティティ 作成時に Microsoft Entra Agent ID が自動プロビジョニングされ、固有の名前・アイコン・メールアドレス・Exchangeメールボックス・カレンダーが付与される。組織図上はオーナーの直属として表示され、M365プロフィールの「Assistant」欄にも登録可能（FAQ）。
二重の権限実行モデル すべての操作を独自IDで行うわけではない。①Autopilot自身のIDで行う操作（同僚へのTeamsメッセージ送信・会議案内など）と、②オーナーの委任権限（On-Behalf-Of）で行う操作（オーナーのカレンダー・メール・ファイル閲覧など）が使い分けられる。オーナーがアクセスできないデータへの権限拡大は起きない（FAQ）。
使用AIモデルとフォールバック 標準は OpenAI（Microsoftサブプロセッサー扱い）提供の GPT-6.1 Sol。管理者が M365管理センター（Copilot > Settings > AI providers）で OpenAI をオフにすると、自動的に Azure OpenAI ホストの GPT-5.6 Sol に切り替わる。ユーザー側からのプロンプトによるモデル切替や個別モデル選択設定は不可（Admin Configure）。
実行環境・PC電源オフ稼働 Microsoft管理のクラウド環境および隔離コンテナ（MXC: Microsoft local containers）上で24時間稼働するため、ノートPCを閉じたり電源を切っても定期ルーチンや長期タスクが継続実行される。ただしローカルPCのフォルダやインストール済みアプリには直接アクセスできない（Overview）。
ブラウザ操作（Edge / Remote Computer） 組織が許可した場合、①クラウド上の Remote Computer で業務Webアプリのフォーム入力・領収書アップロードを行うか、②ユーザー端末でサインイン済みの Microsoft Edge を操作できる。ただしEdge操作はプライベート会話での本人依頼時のみ動作し、定期ルーチンや共有会話では使用不可。閲覧ページ内容はクラウドモデルで処理される（Edge Docs、Mechanics Blog）。
3層メモリと保存先 ①会話メモリ（Conversation）②個人メモリ（Personal）③ワークスペースメモリ（Workspace）の3層を保持。実データはオーナーの OneDrive 内に lobster.repo というGitリポジトリ形式で保存される。タスク実行中の一時ファイルは完了後に破棄される（Admin Configure）。
対応クライアント＆地域・言語 Web（copilot.cloud.microsoft）、Copilotデスクトップアプリ、Teams（1:1チャットおよびチャネル`@mention`）、iOS/Android（M365 Copilot / Teams / Outlookアプリ）。提供開始は米国の対象Frontier顧客限定、言語は英語最適化（他言語UIが表示されても評価済みとは限らない）（Requirements）。

Cowork と Autopilot の使い分けの決め手

「この議事録とExcelから提案書を作って関係者にメール下書きを用意して」のようにゴールが1回で完結する委任作業は Copilot Cowork が適任です。一方、「来月末の製品ローンチに向けて、毎朝チャネルとメールを見張り、停滞している意思決定を拾い、遅れている担当者に催促し続けて」のように時間軸をまたいだ継続フォロー（Follow-through）が Autopilot の真骨頂です。

RPA（Power Automate / UiPath）は不要になるか？

置き換わるのではなく階層分離（補完関係）になります。毎回同じルールで1万件の請求書を処理する構造化業務は、決定論的で低コストな RPA / Power Automate が圧倒的に有利です。Autopilot はその上位で例外判断や人間への調整を担う「認知的オーケストレーション層」として組み合わせるのが最もコスト効率に優れます（RPABotsWorld分析）。

Autopilot のクレジット消費を決める4大ドライバー（公式ガイド準拠）
1. タスク複雑度（Models）

読み込むメール・ファイル・会議数に比例。ただしWork IQランタイム統合によりトークン消費を最大80%削減。

4. 実行アクション（Tools）

メール送信、会議予約、文書更新、Webサイト・ブラウザ操作など、アクション実行ごとに加算。

05. 1 IDモデルの組織設計論：個人秘書型 vs チーム所属社員型

「1つのIDを持つなら、人に付随する秘書として使うべきか、それともチームに1人AI社員を追加する考え方にするべきか？」は、Copilot Autopilot 導入における最大の経営・組織設計テーマです。公式仕様と実務コストの両面から最適解を導きます。

Model A（公式基本形）

個人専属「エグゼクティブ秘書」型

対象者1人に1体のAutopilotを割り当て、個人の受信箱・カレンダー・約束事・会議準備を徹底代行させるモデル。

  • 強み： 個人の文体・優先順位・Memoryが完全最適化され、意思決定者の時短効果が最大。権限境界も明快で情報漏洩リスクが低い。
  • 弱み： 全社員へ横展開すると「$30固定＋従量」が人数分乗算され、投資対効果が薄い層が出やすい。
最適対象：役員、部門長、PM、トップ営業、複数プロジェクト兼務者
Model B（最推奨・実務最適解）

リーダー管轄「チームPMO・AI社員」型

チームリーダー（PM/課長）を正式な Named Manager とした1体を、チームのTeamsチャネルに常駐させ、メンバー全員から @mention で協働させるハイブリッド型。

  • 強み： 1体分の従量課金枠をチーム全員（5〜15名）で共有でき、1人あたり月額コストが数千円レベルまで激減。進捗追跡・決定事項整理・会議設定を自動化。
  • 注意点： オーナー（リーダー）の閲覧権限で読んだ機密情報がチャネルに漏れないよう、参照ソースを当該チャネルと共有フォルダに明示限定すること。
最適対象：開発・DX推進・営業チーム・プロジェクト推進室（まずはここから！）
Model C（アンチパターン・非推奨）

架空の共有アカウント割当型

「sales-team@company.com」等の共有・架空ユーザーを作成してそこにAutopilotを紐づけるやり方。

  • NG理由①： 公式仕様は「責任を負う実在の人間（Accountable User）」への紐づけを前提としており、承認カードや責任の所在が曖昧になる。
  • NG理由②： 従来の人間アカウント流用は Entra Agent ID 設計方針で明確に非推奨。監査証跡・ライセンス規約上のリスクが高い。
代替策：純粋な部門共有Botは Copilot Studio で構築し、Agent 365 で管理する
今後のロードマップ：Copilot Workspaces とのチーム統合（Coming Soon）

Microsoft Ignite 2026 では、現在「個人1対1」を起点としている Autopilot を、次のステップとしてチーム共有の「Copilot Workspaces」へ持ち込んで協働させる機能を「Coming soon」として予告しています（Copilot Coaching Igniteレポート）。また、個人の Autopilot で育てた業務手順（Skills / `SKILL.md`）は、現時点でもチームの他メンバーの Autopilot へリンク共有して複製可能です。したがって、「権限と予算の責任者は人間1人に固定しつつ、働き方とスキルはチーム資産として運用する」のが2026〜2027年の王道設計です。

Conditional Access（条件付きアクセス） 「All users（全ユーザー）」対象のポリシーには Agent ID が含まれない。また、ポリシー変更やユーザーブロックの反映に約1時間かかり、オーナー代理実行中の処理はさらに継続する場合がある。 Agent ID を明示的に対象指定した専用CAポリシーを作成する。緊急停止時は「ブロック」だけでなく支出ポリシーからの即時除外を併用する。

Autopilot は全アクションを実行前に別のAIモデルで検証します（How Autopilot reviews actions）。重要点：オーナー本人のチャット指示のみが権限の根拠となり、メール・ファイル・Webページ内に埋め込まれた指示（間接プロンプトインジェクション）ではアクションが承認されません。ただし管理者・ユーザー側で自動承認システム自体のオン/オフや細かな設定変更は現行リリースでは不可です。

自動実行（無停止）

決済（Payments）、アカウント変更、永久削除など機密ブラウザ操作。承認カードに「常に許可」は存在しない。

07. 管理者セットアップ手順・退職者対応・監査データ出力

Autopilot は既定で無効（Off by default）であり、Frontier を有効化しただけでは使えません。以下の3ステップをすべて完了する必要があります（Admin Configure）。また、支出ポリシーを新規作成できるのはグローバル管理者（Global Admin）と課金管理者（Billing Admin）のみで、AI管理者・ライセンス管理者は既存ポリシーの編集のみ可能です（ISSOH解説）。

STEP 1：Frontier 有効化

M365管理センター > Copilot > Settings > View all で「Frontier」を検索し、Copilot Frontier を特定グループ（検証メンバー）に割り当て。

STEP 2：支出ポリシー設定

Copilot > Cost management > Configuration > Spending policies で新規作成。対象サービスで Autopilot を選択し、月次上限・ユーザー上限・アラート・支払方法（Azure PayGo / 前払）を設定。

STEP 3：Agent Registry 起動

Agents > All agents で Autopilot (Frontier) を選択し Activate。5ステップウィザード（対象ユーザー・支出ポリシー・セキュリティ確認・自律実行権限同意・メモリ確認）を完了。

異動・退職者（Mover / Leaver）発生時の必須オフボーディング手順

注意： アクティベーション対象グループからユーザーを外しただけでは、作成済みの Autopilot は停止しません（Admin Configure、Jazz Security解説）。必ず以下の順序で処理してください。

  1. 支出ポリシーから除外： 対象ユーザーを Autopilot の Spending Policy から外す（新規応答・自動化・監視が停止）。
  2. インスタンスのブロック： Agents > All agents > Autopilot (Frontier) > Instances から該当インスタンスをブロック（反映に最大約1時間）。
  3. 法的・監査エクスポート（必要時）： 下記 PowerShell スクリプトで OneDrive 内の lobster.repo を保全。
  4. インスタンス削除＆ライフサイクル管理： 削除後30日でアカウントとデータが完全消去（監査ログのみ保持）。併せて Entra ID の非アクティブポリシー（60日通知→90日無効化→455日削除、ライセンス不要）を有効化。一括削除や完全消去証明が必要な場合は Microsoft サポートへ依頼。
管理者向け：コンプライアンス・プライバシー対応用データエクスポート手順（PowerShellコマンド＆トラブルシュート）

管理者はユーザー本人の認証情報を使わず、一時的に対象ユーザーのOneDrive管理者権限を付与した上で、GitHub配布の Autopilot-Workspace-Export.zip 内スクリプトを実行して lobster.repo を取得できます（元のOneDrive内容は変更・削除されません）。取得完了後は必ず Set-SPOUser ... -IsSiteCollectionAdmin $false で権限を剥奪します。

powershell -NoProfile -ExecutionPolicy Bypass -File .\Export-AutopilotWorkspace.ps1 ` -TargetUser user@contoso.com ` -Reason "Privacy request 1234" ` -Account admin@contoso.com ` -TargetOneDriveUrl "https://contoso-my.sharepoint.com/personal/user_contoso_com"
出力フォルダ内容（Autopilot export <日時>）
  • Latest files：最新版のメモリ・セッション可読コピー
  • repository.git：過去履歴を含む完全Gitリポジトリ
  • export-manifest.json：実行者・対象・日時・理由・全ファイルSHA-256ハッシュ
  • README.txt：コピーの説明

  • Hosts file already has a different entry：既存の cowork.local.microsoft.com エントリを確認
  • Browser shows a certificate warning：絶対に無視せずタブを閉じセキュリティチームへ報告

09. Autopilotの「育成（OJT）」メソッドと段階的権限委譲

Autopilot は初日から完璧に動く魔法の箱ではありません。人間の新入社員と同じように、「①段階的な権限委譲」「②3層メモリの定期メンテナンス」「③独自スキル（`SKILL.md`）の資産化と横展開」「④承認履歴からのフィードバック」の4サイクルを回すことで、組織固有の優秀な同僚へと育ちます。

育成フェーズ1（1〜2週目）
閲覧・要約・下書き専用（見習い期）

すべての指示に「送信・変更は禁止（Draft only / View only）」を明記。分類精度・事実確認・文体のクセを観察し、誤りをチャットで直接指導して Memory をチューニングする。

育成フェーズ2（3〜4週目）
定例ルーチン＆スキル化（独り立ち期）

安定した業務を Routines へ登録し、繰り返し使う作業手順を Skills（SKILL.md） として保存。社内メンバーへのリマインド等、低リスクな送信から承認カード経由で実行開始。

育成フェーズ3（2ヶ月目〜）
チーム協働＆外部ツール連携（戦力化期）

IT承認済みプラグイン（Figma、CRM、業務Webアプリ等）を接続。Teamsチャネルでの @mention 受付や、育てた優良スキルを同僚の Autopilot へ共有してチーム全体の底上げを図る。

3層メモリの点検・矯正テクニック
  • 定期棚卸し： 設定パネルの Review what [name] knows を月1回開くか、「私について何を覚えている？」「週次報告の好みはどう記憶している？」と直接尋ねる（Memory Docs）。
  • 古い記憶の明示削除： 終了した案件や誤認識は「Project Xの記憶を忘れて」と指示し、必ず再質問して消去完了を確認する（会話削除だけでは記憶は消えない）。
  • ルーチン独立性の原則： 定期ルーチンは作成時の会話文脈を自動継承しないことがあるため、参照ソース・宛先・禁止事項をルーチン指示文の中に完結させて書く（FAQ）。
スキル（SKILL.md）による標準化と安全な共有
  • 2つの作成方法： ①会話内で「会議メモを担当者・期限付きトラッカーにするスキルを作って」と指示して承認保存、②SKILL.md＋補助スクリプト/CSV/JSONをZIPまたはフォルダでアップロード（Plugins & Skills Docs）。
  • 呼び出し： チャット欄で / を入力して明示指定するか、文脈に応じて自動選択させる。
  • 安全な社内横展開： 特定メンバーへスキルを共有可能。共有者の認証情報・接続・権限は一切引き継がれないため、セキュリティを保ったまま業務ノウハウだけを展開できる（スキル内にパスワードや機密情報を書かないこと）。

2026年11月現在、Copilot Autopilot は米国の対象Frontier顧客向けロールアウト段階であり、日本企業の本番全面導入にはまだ時間的猶予があります。しかし、「エージェントを安全に任せられる範囲は、AIの賢さではなく、企業のID・データ権限・FinOps統制力で決まる」ため（ヘッドウォータース Ignite 2026分析）、GA到来前に今すぐ着手すべき4段階の準備ロードマップを提示します。

今すぐ実施（日本展開・GA前：〜3ヶ月）
  • SharePoint/OneDriveの過剰共有棚卸し： Autopilotは秘密度ラベル付きファイルも閲覧可能なため、権限整理と暗号化が最優先。
  • Copilot Credits 従量課金体制の構築： Azureサブスクリプション紐づけ、課金管理者（設定）と経理（閲覧）のロール分離、Spending Policy設計。
  • データレジデンシー方針の決定： OpenAIサブプロセッサー（GPT-6.1 Sol）を許容するか、Azure OpenAI（GPT-5.6 Sol）に限定するかを法務・情シスで合意。
  • 既存Cowork / Studioでの業務棚卸し： 単発業務はCowork、定型大量処理はPower Automate/Studio、継続調整はAutopilotという役割分担表を策定。
パイロット〜本番展開（利用可能化後）
  • 少数精鋭PoC（5〜10名）： 訴訟ホールド対象外の部門長・PMを選定し、1人あたり月額上限（例：$50〜$100＝5,000〜10,000 Credits）＋80%通知アラートを設定。
  • Entra CA専用ポリシー適用： Agent IDを明示対象に含めた条件付きアクセスと、非アクティブ自動無効化（60/90/455日）をオンにする。
  • チームPMOモデルの検証： リーダー管轄の1体をプロジェクトチャネルに配置し、ソース限定ルール下でメンバー全員の`@mention`効果とクレジット単価を測定。
  • ROI評価＆スケール： Agent 365 Business Analyticsで消費クレジットと削減工数を突合し、優良SKILL.mdを横展開。
